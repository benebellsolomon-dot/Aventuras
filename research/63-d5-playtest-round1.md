## Fixed this round (all shipped in the round-1 commit)

1. **Images ignored the story's setting** — the booru writer's context had scene/subjects/location but nothing about the story. Both image LLM prompts now get a `## Story setting` block (genre + description + era-fidelity instruction); template sync v9.
2. **Action choices silently vanished** — three stacked causes, peeled in order:
   a. `ActionChoicesService`/`SuggestionsService` swallowed every error and returned `[]`, so failures were indistinguishable from "no choices" (no toast could ever fire). Removed; failures propagate to the post-phase error event.
   b. Surfacing was toast-only and unreadable; now a persistent amber "Choices unavailable: <error>" panel renders in the choices slot (`ui.actionChoicesError`), plus a 12s toast.
   c. The real failures, per the now-visible errors: hard schema gates (`.min(1).max(4)`, strict enums, ranged dc/essence) voided whole responses on constraint-ignoring providers — softened to coerce-not-reject (`.catch`) with slicing caps and hand-declared TS types; AND minimax returned markdown because its provider claims structured-output support while ignoring `response_format` — `generateStructured` now does ONE corrective retry with the schema forced into the prompt, and its error message carries the model id + cause + a 180-char raw-response snippet.
3. **Scene images rendered without the scene** (bare wall instead of castle/rain/night) — **measured**: replayed the app's real ~120-token prompt and a ~40-token control on `wai-illustrious-sdxl`/NanoGPT; the long prompt lost its entire scene tail, the control rendered everything. NanoGPT truncates at the first 77-token CLIP window (recorded in `providerCapabilities.chunksLongPrompts`, alongside the earlier weighting measurement). Fix: provider-aware tag budget — `BOORU_MAX_TAGS_SINGLE_WINDOW` 36 with per-run identity cap 13 for single-window endpoints; local chunking backends (a1111/comfy/si-bridge) keep 60. The old 60-tag "fits the window" comment's arithmetic was simply wrong (~2 CLIP tokens per tag+comma, not 1.5 loose).
4. **Dagger rendered as a rifle** — the writer emitted `holding dagger, weapon`; with the scene truncated away, the generic `weapon` tag freewheeled into a firearm. Writer instruction: name held items specifically, never bare `weapon`. (Identity banks verified clean of weapon terms via DB query first.)
5. **NSFW image on a SFW scene** — the writer's rating instruction had no scene grounding and its dossier is full of arousal/body stats. `rating` and `action` describes now hard-scope to THIS beat: no act/nudity in scene intent + narrative beat ⇒ general/sensitive, no invented acts, regardless of stats or story rating.
6. **Camera/POV** — new `{{ povGuidance }}`: first/second/hybrid-person stories get protagonist-as-camera framing, third person gets observed-scene framing; template sync v10.
7. Suggestions preset baseline note: GLM 5.2 and minimax both hit the schema gates (2c) before the fixes; with the retry + soft schemas, either should work — re-verify next round.

## Classifier entity routing (found late round 1 — FIXED in the round-1b commit)

**Symptom** (live, both playtest stories): Characters gained a quest ("Camping trip with Amelia") and a plot point ("Lady Elswyth's loaf"); Locations gained the literal string "minutes" as CURRENT LOCATION and a four-sentence event narrative as a location name; Inventory held locations and an event, no items; story beats carried no description.

**Root cause — verified against the persisted deltas, not guessed.** A read-only copy of the app DB (`~/Library/Application Support/com.karelian.aventura/aventura.db`, `story_entries.world_state_delta.classificationResult`) shows the raw classifier output for the junk turns was **filled by position, not by key**: `newCharacters[].relationship` held `"quest"` / `"plot_point"` (story-beat `type` values), `visualDescriptors.eyes` held build text and `build` held clothing, `newLocations[].description` was `"active"`, `locationUpdates` named the known character Cook Maren, `itemUpdates` named the known location The Kitchen, and `scene.currentLocationName` was `"minutes"` while `timeProgression` was `"none"`. Every one of those parses: the schema can only say a name is a string, and the engine created rows from anything string-shaped.
- (a) **Model — confirmed.** The classification preset at the time was `zai-org/glm-5.2` on the NanoGPT profile at reasoning effort `low` (code default is `x-ai/grok-4.1-fast` on OpenRouter). GLM 5.2 is the same model that hit the hard schema gates for suggestions (finding 2c). NanoGPT's provider default is `structuredOutput: false` with per-model capability fetching, so whether the call went through `response_format` or the new prompt-injected corrective retry, the model answered with a positionally-filled object.
- (b) **No accept-time type guards — confirmed** (`applyClassificationResult` + the update handlers stub rows from any unknown name).
- (c) **classifier-bounds — ruled out.** It only bounds the extension arrays (beEvents/agendas/chekhov); base fields are untouched, so it cannot make scrambled base output parse. The new tolerant path that plausibly mattered is the `generateStructured` corrective retry (treats the model as schemaless and injects the schema into the prompt — exactly the mode in which a weak model fills by position).

**Fix (all shipped):**
1. **Accept-time plausibility guard** — new `src/lib/services/ai/generation/classifier-entity-guards.ts` (`guardClassifierEntities`, pure, returns the same object when nothing changes; `knownEntityNames` builds the known sets). Every reject is dropped WITH a recorded reason (`{kind, field, name, reason}`) — logged in dev AND appended to `result._guardRejects`, which rides into the entry's `worldStateDelta.classificationResult`, so a mis-routing provider stays diagnosable in a shipped build — never by failing the turn (research/62 truncate-not-reject). Rules, cheapest first:
   - **HARD vocabulary** (time words `none/minutes/hours/days`, status enums, JSON literals) can never be a name in any case or decoration (`"minutes."`, ZWSP-padded) — applies even to KNOWN names and to `presentCharacterNames`, so a junk "minutes" row can never be re-targeted as current.
   - **SOFT vocabulary** (beat types, item locations, relationship words) rejects only the exact lowercase enum form (`quest`, `inventory`) — `Ally`, `Na`, `Revelation`, `Unknown` are names; known same-type updates bypass it.
   - **Shape**: 80 chars / 12 words (30 chars when spaceless — a CJK paragraph), must contain a letter, not a time phrase (`a few minutes later`), not sentence-shaped (a mid-string `.!?` after a non-abbreviation, non-initial word, or any CJK terminal; `St. Mary's Hospital for the Infirm`, `J. R. R. Tolkien`, and a trailing LLM period all pass).
   - A "character" whose `relationship` is a beat type is a beat (`relationship-is-beat-type`).
   - **Cross-type collision** (exact lowercase match against KNOWN rows): new locations/items/beats may not name a known entity of another type (`The Kitchen` as an item, `Cook Maren` as a location); new characters collide only with known beat titles — a person named like a known place/object (sword-spirit "Dawn") is rare but real, and a lost character is the most consequential false positive.
   - **Paired rejection**: a name rejected from a `new*` array is also rejected from the matching `*Updates` array (the update handler would stub the row from the update alone).
   - **Known-name bypass** for update arrays (the row exists; long user-created names stay updatable); UNKNOWN update names — which would stub a row — are held to the new-entity bar. `scene.currentLocationName` gets the same known-location bypass for shape rules only.
   - **Leaked-enum scrub** on prose fields (`description: "active"`, `relationship: "pending"`, `location: ""`) for new entries AND update `changes` (incl. `descriptionAddition`) — the field is dropped, never the row.
   - Malformed shapes (missing arrays, null entries, non-string names) are coerced, never thrown; accepted entries are kept VERBATIM (checks run on a normalized key — rewriting names would split an existing `"The  Kitchen"` row into a duplicate).
   Wired at BOTH seams: `ClassifierService.classify` after the extension bound (so the persisted delta, image context and translation only ever see accepted entities) and the top of `applyClassificationResult` (so no store caller can bypass it) — idempotent, test-pinned. The real playtest payload is a test fixture: five rejects, the one legitimate Amelia update survives with its leaked `relationship: ''` scrubbed.
2. **Classifier template** gained an "Entity Routing (field discipline)" block (characters = named beings only; locations = places; items = objects rather than places or people; everything else = story beats WITH a required description; `currentLocationName` is a place or null, time goes only in `timeProgression`; fill by KEY not position, omit rather than placeholder — visualDescriptors exempt), a per-beat description requirement (also in the zod `.describe`; the field stays optional in the schema on purpose — a hard gate would void the whole turn on the very providers that omit it), and critical rule 5 (renumbered 1-7). Service template sync **v11**.
3. **Model recommendation for the classification preset:** move it OFF GLM 5.2. Staying on NanoGPT, `moonshotai/kimi-k3` is the validated choice — it already drives the booru structured writer this round without a single routing failure; on OpenRouter the code default `x-ai/grok-4.1-fast` is the known-good structured-output model. Not A/B-measured here (no live calls in this pass) — verify in round 2 by inspecting `_guardRejects` on new entries' deltas (or the dev log line `entity guard dropped…`): a healthy model should produce zero rejects per turn.

**Existing junk rows (manual cleanup — delete via the world panels; no helper added):** story d97724f2: characters "Camping trip with Amelia", "Lady Elswyth's loaf"; locations "minutes" (current) and the 208-char "Amelia challenged her stepfather…" narrative; items "The Manor Study", "Spar with Amelia", "The Kitchen"; beats "The Manor Study", "Star Chart" (no description). Story 6a5083ca: location "minutes" (current). Deleting the "minutes" row leaves no current location until the next turn's classifier sets one — expected. The guard prevents new ones; it does not retro-clean. Known behavior change worth stating: a turn whose classifier output was ENTIRELY junk now reads as signal-less to the agenda/chekhov engines (they pause for that turn, as on a provider hiccup) — intended; a junk-only classify is a failed classify.

**Tests:** 24 unit (`classifier-entity-guards.test.ts`, incl. the playtest fixture, idempotence, malformed-shape coercion, the review's false-positive corpus) + 2 store-harness cases (no `addCharacter/addLocation/addItem/addStoryBeat` for junk, legit entities still written, `_guardRejects` persisted in the delta, a known junk "minutes" location cannot be re-targeted as current). Suite 1326 → 1352.

## Round 1b-2: DC chips and typed-action checks vanished after the preset switch (FIXED)

**Symptom** (Ben, after moving the presets onto kimi-k3 / deepseek-v4-pro on NanoGPT): action choices rendered with no skill/DC chips; no error, no empty-choices panel — choices just came back untagged. The persisted `action_choices:<storyId>` rows confirm it: the latest choices for the playtest story carry only `text`/`type`/`targetCharacter`; an older story's rows still have `skill`/`dc`.

**Root cause (verified offline).** Two layers, same family as finding 2c:
1. NanoGPT flags these models `structuredOutput: true`, so the app sends `response_format` json_schema and — because `supportsStructuredOutput` was true — does NOT render the schema into the prompt. The upstream models don't enforce the json-schema constraints, so the model only ever sees the prose instruction ("add `skill` and `dc` fields… valid skill ids: …") and writes whatever shape it likes. A live probe of deepseek-v4-pro WITH the TypeScript type rendered into the prompt (the prompt-schema middleware's exact format) returned correct lowercase skill ids and numeric `dc` on the first try — the model is fine, it just wasn't shown the type.
2. The round-1 `.catch(undefined)` coercions on `skill`/`dc`/`essenceCost` made off-shape values disappear SILENTLY: `{skill: "Perception", dc: "12"}` parses "successfully" to `{}` (probe-verified). `riskassess.ts` was still a strict enum, so the same shapes failed the whole parse — which `RiskAssessService` swallows into "not risky" — so typed-action checks died the same way. Net effect of round 1's coerce-not-reject: the failure moved from "every choice vanishes" to "every chip vanishes", still invisible.

**Fix:**
- New `src/lib/services/ai/sdk/schemas/tolerant-fields.ts` — tolerant shared fields: `skillIdField` ("Perception", "athletics (STR)", "Stealth check" → id via exact fold then unique-whole-word fallback; unknown → unset WITH a `console.warn` naming the field and raw input — release builds too, the debug logger is dev-only), `boundedIntField` ("12" → 12, 11.6 → 12, out-of-range → unset + warn), `looseBooleanField` ("true"/"yes"/1 → true), `looseStringField`, `looseEnumField` / `looseOptionalEnumField` (case-folded; off-list → fallback/unset + warn). Used by action choices (`type`/`skill`/`dc`/`essenceCost`/`growthIntent`), risk-assess (every optional field — the review caught that `growthIntent: "true"` alone still voided the verdict), suggestions (`type`), and the classifier's own enums (character `status`, beat `type`/`status`, `scene.timeProgression` — a cased "Active" or "Quest" used to void the WHOLE turn's classification, silently, via the empty-stub fallback). The response_format JSON schema is byte-identical before/after (reviewer-diffed; test-pinned: enums, integer bounds, descriptions, `required` survive the wrappers) — nothing changes for OpenAI/OpenRouter strict mode.
- Provider capability `structuredOutputUnenforced: true` on NanoGPT (`providers/config.ts`): when set and the model takes `response_format`, structured calls ALSO render the schema into the prompt (`promptSchemaMiddleware({ keepResponseFormat: true })`, new option) — JSON mode still helps, but the model must SEE the type. Wired through `resolveConfig → buildStructuredMiddleware` for both `generateStructured` (the corrective retry stays prompt-only) and `streamStructured`. Other providers are untouched.
- Three existing tests were CHANGED (flagged deliberately): `riskassess.test.ts` "rejects unknown skills and out-of-range dc" and "rejects a non-boolean growthIntent", and `actionchoices.test.ts` "coerces a non-boolean growthIntent" (its input `'yes'` is now a recognised boolean word) — each pinned exactly the strict/silent behavior that was the bug; the replacements assert the new contract and carry a comment saying so.
- Tests: `tolerant-fields.test.ts` (normalisers, schema shapes, classifier enums, an inferred-type assignability pin), `promptSchema.test.ts`; suite 1353 → 1368.
- Review (one Opus pass on the diff): fixed the HIGH (four un-caught risk-assess fields), the DEV-only logging, the whole-word skill fallback, the `looseEnumField` type widening, the inaccurate cast comment, the `dc.maximum`/`required` test gap, and the classifier-enum scope gap. Accepted: coercion removes the corrective-retry second chance for a genuinely off-list skill (a recoverable failure becomes "safe, with a warn" — with the schema now in the prompt, off-list skills should be rare); `looseInt` accepts `"0x0c"`/`"1e1"` (harmless); `"1-3"` essence drops with a warn rather than guessing; the injected TS block costs ~430 tokens per structured NanoGPT call and renders `integer` as `number` (the descriptions carry the rubric); BE/agenda/chekhov extension-schema enums not touched (their extractors already sanitize-and-truncate); `resolveConfig`'s `promptSchemaAlongside` wiring is untested (needs the settings store mocked) — covered by the in-app round-2 check.

**Not live-verified in-app** (no live calls from this pass beyond the deepseek probe): round 2 should confirm chips on deepseek/kimi via NanoGPT, and watch the console for `[TolerantFields]` warnings — each is a model shape worth adding to the normaliser.

**Round 1b-3 follow-up (same evening, after Ben's screenshot still showed four untagged choices — two domestic `action`s, two `dialogue`s — plus a level gained and "essence used"):**
- The level and essence are engine-correct, not a bug: levels come from BE interaction-milestone CROSSINGS (`rpg/leveling.ts` — a girl's carried mass passing a threshold), and `essenceMax(level)` = 6 + 2·level, so the bar went 8/8 → 8/10 — max rose, nothing was spent.
- Chips: a second deepseek-v4-pro probe on the SAME domestic attic scene, with the schema rendered into the prompt, tagged 3 of 4 choices (persuasion 11, channeling 14 ⬡1, perception 11). So the model is willing; the in-app path was still not showing it the type — either the app hadn't reloaded the round-1b-2 code, or NanoGPT's `response_format` json_schema path (sent `strict: true`) suppresses the optional fields under constrained decoding. Decision: **unenforced aggregators now default to PROMPT-ONLY structured output** (`resolveConfig` forces `supportsStructuredOutput=false` when `structuredOutputUnenforced` unless the preset's override is explicitly `on`, which then sends response_format WITH the schema in the prompt). This is the exact path that has worked in every probe and in the round-1 corrective retry; the response_format path has only ever caused trouble on NanoGPT.
- Persisted payloads from an earlier session show models tagging `{skill: 'investigation'}` with NO dc — which both the chip and `CheckPhase` silently treat as untagged. New `DEFAULT_CHECK_DC = 11` (rubric "easy") + `withDefaultDc` applied in `ActionChoicesService` and `RiskAssessService` — a skill without a dc is a check at the default-LOW DC.
- Suite 1368 → 1369. Still not live-verified from here: Ben should restart the dev app (to be sure the new `generate.ts` is loaded), play a turn, and look for DC chips; if still none, open devtools and read the `=== RESPONSE === Output:` log for the action-choices call and any `[TolerantFields]` warnings — that raw output decides it.
